## PREPARED FOR WILL — D2: the Gumroad deliverable

The build is one self-contained HTML file, so all three
shapes are physically possible. What differs is what the
buyer holds, what works without the hosted side, and how
updates and support run.

**The unlock, common to all three (draft, PLAN §2.6): one
key system, two issuers.** A Gumroad purchase issues an
unlock key; a credit gift issues the same kind of key. Both
redeem the same way, at the start screen — one code path,
one support story, one wording. The key is what turns a
free build into a generator's build.

### (a) The downloadable single-file build only

- **What the buyer receives:** the HTML file itself, plus
  their unlock key. They open the file, enter the key once,
  and they are a generator — for life, on that file.
- **Offline / hosted:** everything in the file works
  offline — the taught world, the quest, generation and
  ledgers kept in the local save. What cannot work offline
  is anything shared: marks posting to the shared world,
  the board, and any ledger the world must agree on. Under
  a download-only sale, those either stay hosted-side
  extras the buyer signs in for separately, or they are
  simply not part of the offer.
- **Support and update story:** a downloaded file never
  updates itself. New builds reach buyers only if they
  come back for them — Gumroad's library re-download is
  the channel, and the listing must say so plainly:
  *"Keep your Gumroad receipt — new builds land in your
  library, free, for life."* Support's hardest case lives
  here: a buyer on a three-versions-old file, reporting a
  bug already fixed.
- **Piracy, plainly:** a single file will be copied. The
  key check lives in the same file, so a copied file with
  a copied key — or a patched check — is a matter of time,
  and no DRM worth having exists for one HTML file. What
  the design actually holds is not the file but the hosted
  world: a copied game cannot post marks, stand on the
  board, or have its gifts honoured, because those run
  through the phext.tech sign-in and the gateway, not
  through the file. The honest posture: the $5 buys
  standing in the shared world and a clear conscience,
  not an uncopyable artifact.

### (b) Hosted access only

- **What the buyer receives:** no file — an account-bound
  unlock. They buy on Gumroad, redeem the key against
  their phext.tech sign-in, and play at the hosted game,
  where their generator status simply *is on*.
- **Offline / hosted:** nothing works offline; there is
  nothing to open offline. Everything works hosted —
  shared world, ledgers, board — with no seam, because
  there is only one side.
- **Support and update story:** the best of the three.
  The hosted side updates silently: every buyer always
  plays the current build, fixes arrive without anyone
  re-downloading anything, and support never asks "which
  file do you have?" The cost is the mirror image: the
  "for life" promise now rests entirely on the hosting
  staying up — if the hosted game ever goes dark, a
  lifetime buyer holds a key to a door that isn't there.
- **Piracy, plainly:** the least copyable shape — there
  is no artifact to copy, only an account to share, and
  account sharing is bounded by the sign-in. This is the
  one real anti-piracy property in any option, and it is
  bought with the offline loss above.

### (c) Both — download and hosted, one key

- **What the buyer receives:** the file to keep, and the
  same key redeemed against their phext.tech sign-in for
  the hosted game. One purchase, two doors, one key path
  (Gumroad and gifts alike, per §2.6's draft).
- **Offline / hosted:** the downloaded file plays whole
  offline, generator status included, ledgers in the
  local save. The hosted side adds what only it can:
  shared-world marks, the board, world-agreed ledgers.
  The seam must be worded honestly on the listing: your
  world travels with your file; the shared world lives
  at the hosted game.
- **Support and update story:** both stories, run
  deliberately. Hosted players are always current
  (silent updates). Download holders get new builds
  through their Gumroad library, announced on the
  listing, free for life — and support's first question
  ("hosted, or which build?") is a known, bounded cost.
- **Piracy, plainly:** same truth as (a) — the file will
  be copied, and the design's answer is the same: the
  hosted world's value (marks, board, honoured gifts) is
  what a copy cannot take. (c) states that answer most
  honestly, because the buyer can see both halves: the
  file is theirs to keep; the world is theirs to stand in.

**Interaction with D3 and D4 (context, not decided here):**
D3 — go-live is Will's one sudo install of the staged
build. Under (a), the sale can point at the download
first and go-live can follow; under (b), go-live *is*
the product and must land before or with the listing;
under (c), the download can sell from day one while the
sudo install lands on Will's timing, with hosted access
switching on when it does. D4 — the Gumroad account is
Will's hands (identity / payout); every option's listing
work is staged to start the hour the account exists, and
no option changes that.

### RULED (Will, 2026-11-26 14:46 CST) — versioning by ship epoch

### RULED (Will, 2026-11-26 14:50 CST) — customizable player forms

**Players have customizable forms: any description that
renders within a player-sized bounding box and fits in
4 KB of phext.** The form is the player's own description,
written as phext, under two hard constraints — the render
must fit the player-sized bounding box, and the
description itself is at most 4 KB of phext. (Fit is a
property of the render, checked against the box; the 4 KB
is a property of the phext. Corrected by Will, 2026-11-26
14:50 CST: phext, not plain text.) Not assigned to a tier — launch-day features are
everyone's under the D1 remainder ruling. Enters the dev
loop's queue behind the in-game idea door.

**Refinement (Will, 2026-11-26 14:51 CST):** the player
sprite is **frame-svg-capable** — a form's animation frames
can be SVG, rendered as the sprite frame inside the
bounding box; fit is checked on the SVG's rendered bounds,
and SVG content counts toward the 4 KB phext cap.

**Leeway direction (Will, 2026-11-26 14:51 CST):** "give
them a lot of leeway, experiment with higher limits" —
the 4 KB / player-box numbers are the baseline; the form
system is built with tunable limits and an experiment at
materially higher caps, shipping a generous experimental
default for Will's ratification. (The no-script rule for
chart-received SVGs is not part of the leeway.)

**Template types (Will, 2026-11-26 14:52 CST):** form
pages carry **multiple template types, selectable per
form page — svg, bitmap, turtle, etc.** — the criterion
for any type is that it makes drawing simple/easy/fast.
Animation may mix types across frames of one form.
